# 파이프라인 버전 관리 선례 조사 — 증명된 방식과 우리 적용안

> 2026-08-20. 배경: 구조화·클러스터 조합(run) 버전 관리 UI가 커지며 관리가 어려워짐 →
> 업계에서 같은 문제를 어떻게 풀었는지 조사. 웹 리서치 + 레포 3개 코드 탐독
> (`references/`에 클론: langfuse · mlflow · promptfoo — gitignore 대상).

## 1. 지형 (2025–2026) — 어디로 수렴했나

| 결론 | 근거 |
|---|---|
| **run = 조합 스냅샷**은 업계 표준 | MLflow 3.x LoggedModel(앱버전 = git+config+프롬프트버전 링크 허브) — 우리 doc_runs와 동일 개념 |
| **활성화 = 라벨 재할당**으로 전 업계 수렴 | MLflow: 고정 stages **폐기** → aliases. Langfuse: production 라벨 재할당=배포, 되돌림=롤백 |
| run 비교 UI는 단일 패턴 | 목록=차원이 컬럼인 표 → 다중 선택 → **차이만 하이라이트** (MLflow·ClearML·DVC 동일) |
| 프리셋 = 기본 대비 오버라이드만 | Hydra config group(=우리 "라인") + experiment 파일 패턴. 단 run 생성 시 전체 스냅샷 고정(우리가 하는 방식) |
| UX 킬러 2종 | ClearML: **clone→일부 수정→새 run**. Dagster: **stale 배지**(활성 run 이후 차원 갱신 시 "뒤처짐" 표시) |
| 기타 | DVC는 2025-11 lakeFS에 인수(데이터 버저닝 통합 중). GenAI 실험 비교 단위는 run이 아니라 **아이템(문서)** |

## 2. 레포 3개에서 배운 것 (코드 근거)

### Langfuse — 라벨 모델·비교 뷰 (우리와 가장 근접)
- **버전=불변 행, 라벨=다중값**. 라벨의 "이름당 유일"은 앱 코드+트랜잭션으로 강제(배열 컬럼 한계).
  → **Oracle은 더 잘할 수 있음**: `run_labels(키, label)` 별도 테이블 + UNIQUE 제약(DB 강제).
- **라벨 재지정 트랜잭션 순서**(promptRouter 812-1005): 권한 → diff → 보호라벨 검사(양방향) → **의존성 역참조 검사(제거 라벨을 핀한 대상 있으면 CONFLICT)** → 감사로그 → [부여+이전 보유자 회수] 단일 트랜잭션 → **커밋 후에만** 캐시 무효화 → 영향 전체에 이벤트.
- `latest`는 시스템이 옮기는 포인터(생성 시 자동 부여·이전 버전에서 회수), 사용자 라벨 아님.
- 라벨 편집 UX: 팝오버 안 **로컬 스테이징 + 명시적 Save**, 버튼 문구가 결과 예고("Save and promote to production").
- 버전 이력 = 테이블 아닌 **CSS 타임라인 40줄** + 행당 검색문자열 1개(`# 3;메모;라벨들`)로 통합 검색.
- diff = 선택 버전 vs hover 버전 2-way, line→word 2단(jsdiff), side-by-side. chat은 JSON 키 정렬 후 비교(가짜 diff 제거).
- **비교 화면: 행=아이템, 열=run** (`runs: Record<runId, item>` 맵 — 열 추가/삭제에 데이터 재구성 불필요). baseline은 URL 파라미터, diff는 `+0.12` 배지(레이턴시·비용은 색 반전). **집계는 run 목록 화면, 개별 출력은 비교 화면으로 분리**.
- 함정 2개: `isActive Boolean` = 라벨로 갈아타며 남은 사체(활성 플래그로 출발하지 말 것 — **우리가 지금 active='Y'**), labels 배열엔 인덱스 없음(별도 테이블이 정답).

### MLflow — alias 저장·비교 diff·동적 컬럼
- **alias 테이블 PK = (name, alias), version은 일반 컬럼** → "alias는 반드시 한 버전만"을 DB가 강제. **승격 = MERGE(upsert) 한 문장** — 재지정/신규/이동이 같은 코드 경로.
- 재지정 충돌은 차단 아닌 **사전 경고**: "이 alias는 v3에 있고, 저장하면 v3에서 제거됩니다" 배너 → 확인 모달 단계가 사라짐.
- 편집 모달 = `existing[]/draft[]` 두 배열 + 저장 시 diff(added→PUT, deleted→DELETE).
- **비교 뷰 = 전치+합집합+첫값비교 3줄**: 키 합집합 → 키별 값 배열(없으면 undefined) → `values.some(x=>x!==values[0])` 하나로 "차이만 보기" 필터와 하이라이트 동시 구동. 하이라이트는 JS가 클래스만, 색은 CSS 변수.
- 동적 열 식별자 = `` params.`키` `` canonical 문자열 하나(colId·정렬·URL·서버 order_by 겸용). 동적 열 키는 **누적 Set**(사라진 키로 열이 깜빡이지 않게), 표시는 `selectedColumns[]` 단방향.
- champion/challenger는 코드 아닌 관례(placeholder+문서). `latest`·숫자는 예약어, `[A-Za-z0-9_-]` 화이트리스트를 서버·클라 양쪽에.

### promptfoo — 조합 그리드
- **조합 좌표는 이름이 아닌 정수 인덱스 (test_idx, prompt_idx)** — 라벨 중복으로 열이 조용히 합쳐지는 실제 버그 이력이 주석에 남음. 복합키 + 위치 인덱스로 못박기.
- 열 정의(조합 확정)를 실행 스케줄과 분리 → 실행 전 그리드 골격 렌더 + **희소 매트릭스**(특정 조합 스킵) 지원.
- 정규화 저장(셀=1행) + 비정규화 전송(`{head, body}` 위치 정렬 배열) 2계층 — 프론트에 조인 로직 불필요.
- **필터 WHERE를 SQL 한 곳에** 몰고 행 조회·지표 집계가 공유("표는 20건인데 통과율은 전체 기준" 불일치 원천 차단). Oracle은 JSON_VALUE 함수 인덱스로 대응.
- 열 헤더 = 스코어카드 겸 필터 컨트롤: provider 칩 + `78% passing (a/b filtered, c/d total)` + 에러 칩(클릭=필터).
- **실패는 3상태**: 검증실패(ASSERT) vs 호출에러(ERROR) 구분 — 우리 excluded/error 구분과 일치, 유지.
- 셀 diff는 JSON/문장/단어 자동 선택 후 `<ins>/<del>` 시맨틱 태그만(jsdiff 하나면 충분).
- 뷰 상태 전부 URL 쿼리(공유/뒤로가기/새로고침 공짜).

## 3. 우리 콘솔 적용안 (제안)

**P1 — 활성화를 라벨 모델로** (가장 큰 구조 개선)
`run_labels(source_name, label, run_id)` PK(source_name,label) 신설. `active` 라벨이 기존 active='Y'를 대체(마이그레이션: 활성 run→active 라벨 시드, 기존 컬럼은 당분간 동기 유지). 승격=MERGE 한 문장+델타 가산/감산은 기존 activate_run 재사용. 롤백=라벨 되돌림, staging 등 추가 라벨 공짜. Langfuse 트랜잭션 순서(경고→단일 트랜잭션→커밋 후 캐시) 준수.

**P2 — run 비교 뷰** (UI 관리난의 직접 해법)
run 목록에서 2+개 체크 → 비교 패널: 행=차원/설정 키(합집합), 열=run, 첫값비교로 diff 행 하이라이트 + "차이만 보기" 토글. MLflow 3줄 알고리즘 그대로. 결과 카운트(반영/제외/오류)도 같은 표에.

**P3 — 문서 단위 결과 비교** (Langfuse 패턴)
행=문서(src_id), 열=run — doc_results가 이미 (run_id, src_id) 정규화라 바로 가능. baseline run 지정 + 상태 변화 배지(done→excluded 등) + 추출 엔티티 나란히.

**P4 — UX 소품**: run 행 [복제해 새 run](clone→수정), 활성 run stale 배지(스냅샷 이후 차원 기본 버전이 바뀌면 "구성 뒤처짐"), 비교 상태 URL화.

**하지 말 것**: 활성 boolean 유지한 채 기능 확장(Langfuse의 isActive 사체), 라벨을 CSV 컬럼으로(별도 테이블+UNIQUE), 열 식별을 라벨 문자열로(위치/키 canonical).
