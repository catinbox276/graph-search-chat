불러오는 중
엔티티가 무엇인지 — 이 화면 읽는 법
여기서 정의하는 건 "틀"이고, 구조화가 돌면 그 틀로 실제 노드가 찍혀 나옵니다. 예를 들어 속성 library 하나를 정의하면 문서마다 Keras·pandas 같은 값이 뽑혀 그래프 노드가 되고, 같은 값은 전역 1개로 합쳐져 여러 문서가 그 노드를 공유합니다.
  • 계층 칸(2~5개) — 그래프 2층부터 순서대로 쌓이는 뼈대. 첫 칸이 🔗 진입점(질문이 들어오면 여기서 검색 시작)
  • ⭐ 검증귀속 — 성공/실패 카운트와 추천이 붙는 칸. 계층 중 하나를 고릅니다(기본 마지막)
  • 속성 — 진입점 바로 아래 붙는 부가 정보(PostgreSQL·분류 등). 같은 값은 그래프에서 노드 1개로 합쳐지고, 사용자가 그 값으로 물어도 사례를 찾을 수 있습니다
  • 노드를 끌어서 자리를 옮길 수 있습니다 — 선이 겹칠 때 보기 편하게. 배치는 이 브라우저에만 저장되고 [↺ 자동 정렬]로 되돌립니다 (스키마와 무관)
  • 이 스키마 한 벌이 문서 구조화와 대화(세션) 추출 양쪽에 쓰입니다 — 버전은 없고 저장은 덮어쓰기입니다
키·표시명·설명은 전부 바꿔도 됩니다. goal·approach는 기본 이름일 뿐입니다. 층 번호에 대해: 계층 칸은 2층·3층…으로 깊이를 뜻하지만, 속성(9)·행동/도구(8)의 번호는 깊이가 아니라 종류를 가르는 칸 번호입니다 — 계층 체인이 7층까지 늘어날 수 있어 그 뒤 번호를 비워뒀습니다. 속성은 실제로 진입점 바로 아래 한 칸에 붙습니다. (행동/도구 노드는 대화에서 자동 생성)
1️⃣ 도메인 지침 — 어떤 문서를 이 도메인의 지식으로 인정할지. 여기가 비면 LLM이 도메인 이름만 보고 판단합니다
지침·엔티티·뽑는 방식·병합은 한 묶음입니다 — 아래 [💾 저장]이 전부를 함께 저장합니다
2️⃣ 뽑아낼 엔티티 — 노드를 클릭해 오른쪽에서 채웁니다. 끌어서 자리를 옮길 수 있습니다
3️⃣ 뽑는 방식 지침 — 값을 어떻게 일반화할지 (선택, 빈값=코드 기본). 인정/제외 기준은 위 도메인 지침에
4️⃣ 병합(dedup) 설정 — 같은 뜻의 문구를 한 노드로 합치는 기준 (기본값 권장)
임계값을 낮추면 더 많이 합쳐지고(과병합 위험), 높이면 비슷한 노드가 갈라집니다. 애매한 구간에서만 LLM에 "같은 의도의 후보 번호를 골라라"고 1회 묻습니다.
⚙ 도메인 등록·삭제 (고급) — 1층 닫힌 목록, 사람 전용
도메인용도도구 (쉼표구분)우선순위지침동작
